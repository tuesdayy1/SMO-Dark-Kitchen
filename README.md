# Имитационное моделирование СМО — вариант №22

**Тема:** Автоматизированная фабрика-кухня с мультибрендовой системой заказов (Dark Kitchen)  
**Автор:** Аслямов М. Р., группа 5130904/40106  
**Язык планируемой реализации:** C++  
**Текущий этап:** проектирование системы и подготовка первичных артефактов.

## Цель работы

Спроектировать и в дальнейшем реализовать имитационную модель системы массового обслуживания (СМО), соответствующую индивидуальному варианту №22. Модель должна воспроизводить поступление заявок, постановку в ограниченный буфер, выбор заявок и обслуживающих приборов, отказы при переполнении и сбор статистики.

Моделирование планируется вести **методом особых событий**: модельное время переходит к ближайшему событию (поступление заявки или окончание обслуживания).

## Бизнес-домен

Рассматривается **Dark Kitchen** — фабрика-кухня без зала для посетителей, работающая на доставку блюд от нескольких виртуальных ресторанных брендов через единый ИТ-хаб.

- **Заявка** — электронный заказ на приготовление блюда с идентификатором источника и временем поступления.
- **Источники** — цифровые витрины ресторанных брендов; их заказы имеют заданные приоритеты.
- **Буфер** — ограниченная электронная очередь заказов, ожидающих приготовления.
- **Приборы обслуживания** — программные повара-универсалы: алгоритмы, управляющие роботизированными станциями технологических линий.
- **Диспетчеры** — тоже программные алгоритмы: они ставят заявки в очередь, выбирают заявки для обслуживания и распределяют их между приборами. Людей в контуре обслуживания нет.

Описание предметной области и её соответствие элементам СМО представлены в документах ниже.

## Формула индивидуального задания

`ИБ · ИЗ2 · ПЗ1 · Д1ОЗ2 · Д1ОО4 · Д2П2 · Д2Б4 · ОР1 · ОД1`

| Код | Расшифровка |
|---|---|
| **ИБ** | Бесконечные источники заявок |
| **ИЗ2** | Равномерный закон распределения интервалов генерации заявок |
| **ПЗ1** | Экспоненциальный закон распределения времени обслуживания |
| **Д1ОЗ2** | Постановка в буфер в порядке поступления со сдвигом |
| **Д1ОО4** | При переполнении вытесняется последняя поступившая в буфер заявка |
| **Д2П2** | Выбор свободного прибора по кольцу |
| **Д2Б4** | Выбор на обслуживание по приоритету номера источника, по одной заявке |
| **ОР1** | Сводная таблица статистических результатов в автоматическом режиме |
| **ОД1** | Календарь событий, содержимое буфера и состояние системы в пошаговом режиме |

При нескольких заявках одного источника на обслуживание выбирается самая ранняя. Так рекомендует методическое пособие: правило выбора согласуется с дисциплиной отказа, а по Д1ОО4 в отказ уходит самая новая заявка.

## Принятые проектные решения

- **Одновременные события.** При равном модельном времени сначала обрабатывается `SERVICE_END`, затем `ARRIVAL`: освободившийся прибор успевает принять заявку, и лишнего вытеснения не происходит. При полном равенстве события упорядочиваются по порядковому номеру постановки (`seq`).
- **Статусы заявки.** `WAITING` ставится при генерации, `SERVICING` — при начале обслуживания, `DONE` — при завершении, `REFUSED` — при вытеснении из буфера.
- **Статистика отказов.** Вытесненные заявки сохраняются отдельно; время, проведённое ими в буфере, учитывается во времени пребывания в системе.
- **ОР1** содержит показатели по каждому источнику и общие (`total`).

## Сценарии, отражаемые в проектировании

1. Поступление заказа и немедленное назначение при наличии свободного прибора (Happy Flow).
2. Постановка заявки в буфер при занятости приборов.
3. Вытеснение заявки по дисциплине **Д1ОО4** при полном буфере.
4. Выбор заявки из буфера по **Д2Б4** и поиск свободного прибора по **Д2П2**.
5. Завершение обслуживания, освобождение прибора, регистрация результатов и продолжение обработки событий.
